# ⚫⚪ ひっくり 〜HiQRi〜

LINE の友だちと、石をひっくり返して対戦する盤のゲーム。名前は「ひっくり」（石をひっくり返す）。英字は HiQRi（おくるん＝OQRN・キロっく＝kiloQ と同じ作り方で、「く」を Q にする。Q の後ろも「Ri」と大文字で、ロゴは Hi を黒・Ri を白の石の色に分ける）。「オセロ」は登録商標なので、画面・招待カードの名前は「ひっくり」にする。

アイコン（`assets/icon.svg`・`icon-32.png`・`apple-touch-icon.png`・`icon-512.png`・`icon-maskable-512.png`）・横長のロゴ（`assets/logo.svg`）・共有したときの画像（`assets/ogp.png`）は `python3 tools/icon.py` で作る（図形を描く部分は `tools/brandkit.py`。pomodoro・countdown・gender-reveal と同じファイル）。盤の緑にうっすら盤の線。Q の輪は白と黒の2本の矢印が追いかけ合う「入れ替え」の矢印。Q のしっぽは、輪の中から外へ斜めに刺さって突き抜ける石（少しだけ上から見た円盤を細長く。上の面が白、厚みが黒）で、O に棒が刺さった Q の形。黒い矢印はこの石の下から出る。ホーム画面に追加したとき用に `manifest.webmanifest`。

おくるんのトップの「ほかのツール」（line-share の `data/hub-links.json`）には「ひっくり 〜HiQRi〜」として、このアイコン付きで載せている。


LIFF、Firebase Firestore、PeerJS を使った 2 人対戦オセロです。

## 遊び方

- 👥 友だちと対戦：LINE で招待して、それぞれの端末で通信対戦します
- 🤖 COM と練習：この端末だけで COM と対戦します
- 📱 1台で2人：1台の端末を交代で使って、黒の人（先手）と白の人（後手）で対戦します。色の入れ替えはありません
- 盤面の上のカードは、どのモードでも先手（黒）を左、後手（白）を右に並べます
- 友だちを待っている間は、盤面に「友だちを待っています」とアニメーションを出します。ホストは待つ間に START で COM と練習できます（ルームは開いたまま招待も続けられる）
- 練習中に友だちが参加したら、ホストは「友だちと最初から対戦」か「今の盤面を友だちと続ける」を選びます。選ぶまで、友だちはホストの盤面を見て待ちます
- 友だちが参加すると、ホストの画面にお知らせを出します（振動・短い音・別のタブを見ているときはタブの題名でも知らせる）
- OGP（`assets/ogp.png`）とアイコン（`assets/favicon.svg` ほか）は `assets/` にあります
- 始めるまでの流れ：入口で遊び方を選ぶ（この時点では盤面は出さない）→「対局の準備」で 対戦相手 → 盤面 → ルール（→ 問題）→ 色 の順に決める → 準備の一番下の START。友だち対戦は「LINEで招待」をいちばん上に出し、2人そろったら両方が START を押します

## 教養モード

対局前の設定でホストが「ルール：📚 教養」を選ぶと、置けるマスを押したときに4択の問題が出ます。
正解すると石を置けます。不正解（「わからない」・時間切れを含む）のときは、ライフが残っていればライフが1つ減って同じ人がもう一度マスを選べ、ライフがなければ石を置かずに相手の番になります。

- ライフ：なし / 1 / 3 / 5（初期値 3）。石の数が同じで終わったら、ライフが多く残っているほうの勝ち（ライフも同じなら引き分け）
- 回答タイム：なし / 10 / 20 / 30 秒（初期値 なし）。時間が来たら時間切れ（不正解あつかい）。COM には時間制限はありません
- 回答：4択 / ✏️ 入力（初期値 4択）。入力は、漢字の読み（ひらがな・カタカナどちらでも）・数学・一般教養で使い、英単語・ことわざ・四字熟語の意味は4択のままです。全角/半角・カタカナ/ひらがな・空白・「・」などのゆれは同じとみなします。JSON のレベルに `"input": true` を書くと入力で答えるレベルになります

- 盤面は 6×6 / 8×8 から選べます（ふつうのルールでも選べます）
- 問題は「ジャンル×レベル」をいくつでも選べます（例：漢字・中学＋英単語・高校＋数学・小学）。選んだものをまとめて混ぜて出します。4択の選択肢は、その問題と同じジャンル・レベルの中から選びます
  - ジャンルとレベル：漢字（小学・中学・高校）、英単語（中学・高校・大学）、ことわざ・四字熟語、一般教養（やさしい・むずかしい）、数学（小学・中学・高校・大学の微積）
  - ルールは `{ mode, size, picks: [{ genre, level }], seed }`。以前の `{ genre, level }` 形式も読めます
- ホストは対局が終わったあとも、そのまま上の設定欄でルールを変えられます。変えると、相手（通信対戦ならゲストも）といっしょに次の対局の準備に移ります
- 問題は「問題の種・マス・そのマスで何回目の挑戦か・不正解のあとに割り当てた山の位置」から決まるので、通信対戦でも両方の端末で同じ問題になります（問題そのものは送りません）。不正解だったマスは次に別の問題になります
- 盤面の中で同じ問題は出ません。言葉の問題は種で並べ替えた順に空きマスへ1つずつ割り当て、数学は同じ問題文ができたら作り直します
- 不正解のあとは、まだ一度も出していない問題を順番に使います（`quizRetries` にマスごとの位置を記録し、両方の端末で同じ順に割り当てる）。使い切ったら、いま空きマスに出ていない問題から選ぶので、空いているマスどうしで問題が重なることはありません。問題の数が「空きマス＋不正解の回数」より少ないと同じ問題がまた出ることがあるため、各レベルは多めに用意するか、複数のレベルを混ぜてください
- 対局中は、空いているマスにそのマスの問題の1文字を表示します（4隅だけは「？」。漢字・ことわざ・四字熟語：そのレベルでいちばん珍しい漢字、英単語：頭文字、一般教養：問題ごとのキーワード `m`、数学：問題の種類の記号）。一般教養の `m` は、正解にだけ入る字にしないでください（答えの手がかりになるため）
- 問題の種は START のたびに作り直すので、再戦でも別の問題になります
- 数学はその場で計算して作るので、答えは必ず正しくなります
- 数学の問題文と分数の選択肢は、KaTeX（TeX 互換の数式組版）で組みます。数学を選んだときだけ CDN から読み込み、読み込めるまで・読み込めないときは普通の文字で出します。JSON の問題も `"tex": "$x^2$ の係数は？"` のように書けば数式で組みます（`$…$` の中が TeX）
- 言葉の問題は `questions/*.json` の [問い, 答え] の組から作り、まちがいの選択肢は同じレベルの別の組の答えから選びます。同じレベルの中に意味が重なる組を入れないでください
- COM は、そのマスの問題のレベルに応じた確率で正解します
- 相手（友だち・COM）が答えている間は、その問題と選んだ答え・結果を見るだけのシートで表示します。シートの「隠す」で以後は「相手が回答中…」の小さな表示だけになり、そこを押すとまた見られます（設定は端末ごとに保存）。通信対戦では「どのマスの何問目か」と「選んだ番号」だけを送ります

### 問題を追加する（JSON）

`questions/` に JSON ファイルを1つ置くと、ジャンルとして読み込まれます（数学は計算で作るので組み込み）。

```json
{
  "id": "history",
  "label": "日本史",
  "icon": "🏯",
  "order": 50,
  "levels": [
    {
      "id": "basic",
      "label": "やさしい",
      "type": "choices",
      "items": [
        { "q": "鎌倉幕府を開いたのは？", "a": "源頼朝", "w": ["足利尊氏", "徳川家康", "平清盛"], "m": "鎌" }
      ]
    },
    {
      "id": "words",
      "label": "用語",
      "type": "pairs",
      "template": "「{q}」の読みは？",
      "mark": "rare-kanji",
      "items": [["埴輪", "はにわ"], ["勘合", "かんごう"]]
    }
  ]
}
```

- `id`：ジャンルの id（ルールに残るので、公開後は変えない）。数学の `math` や、ほかのファイルと同じ id は読み飛ばします
- `order`：並び順（小さいほど上。今は漢字 10・英単語 20・ことわざ 30・一般教養 40、数学はいつも最後）
- `type: "choices"`：問題ごとに答え `a` とまちがい `w`（3つ以上）を書きます。`m` は盤面に出す1文字（正解にだけ入る字は避ける）
- `type: "pairs"`：[問い, 答え] の組。まちがいは同じレベルの別の組の答えから選びます（4組以上必要）。`template` の `{q}` に問いが入ります。`mark` は `rare-kanji`（そのレベルでいちばん珍しい漢字）か `first-letter`（頭文字）
- 盤面の中で同じ問題を出さないため、8×8 で遊ぶレベルは 60 問以上にしてください
- 形式がおかしい問題・レベル・ファイルは読み飛ばし、ブラウザのコンソールに理由を出します
- 一覧 `questions/index.json` は公開時（GitHub Actions）に自動で作り直します。手元で確かめるときは `sh scripts/build-question-index.sh` を実行してください

## 将来の構想（メモ）

- **観戦モード**：同じルームに3人目以降が入ったとき、満室で断らずに観戦できるようにする
  - 今は「このルームはすでに2人参加しています」で入れない（`js/matchmaking.js` の `resolveEntry` が `full` を返す）
  - コードにある `spectatorMode` は、切断した相手が戻ったときに再開方法を選ぶ間だけ盤面を見せるためのもので、観戦とは別
  - 案：ホストの端末が観戦者にも盤面・手番・回答中の問題（`quiz-open` / `quiz-choice`）を送る。観戦者の盤面は押せない。今の P2P は相手1人を前提にしているので、ホストが複数の接続を持てるようにする必要がある
  - Firestore のルームに観戦者の一覧（または人数）を持つか、観戦者はルームに書き込まずにホストへ直接つなぐかを決める
